# Пятая домашка

Состоит из двух частей (сам код и девопсина).

## Часть первая. Пишем программу для выдачи ипотек

Приложение должно иметь интерфейс для аналитика, который будет принимать решения по выдаче ипотеки. Сами заявки будут храниться в базе данных (файл будет приложен). После одобрения или отказа должен быть создан PDF-файл, который будет храниться в S3-хранилище (MinIO сервер).

### Логика работы сервиса

1. Аналитик открывает заявки по ипотекам.
2. Аналитик выбирает одну из заявок и нажимает кнопку для расчёта.
3. Аналитик либо сохраняет заявку (делает черновиком), либо одобряет или отказывает заявку.
4. Когда происходит решение по отказу или одобрению, создаётся PDF-файл с одобрением или отказом, а также в случае одобрения сделайте график выплат (просто линию, где по оси X — это месяцы и годы, а по Y — полная сумма кредита и потом на каждый месяц уменьшение на ежемесячную выплату).
5. Результат сгенеренного файла можно  глянуть в MinOI админке.

Изначальные ипотечные заявки будут лежать в базе данных (вам нужно будет создать образ на основе Postgres и файлом с пользователями).
Структура таблиц будет уже дана, у каждой из табличек будет флаг о решении заявки, который имеет поле «черновик», «отказано», «одобрено».
Файл с  заявками лежит в ресурс папке applications.sql

### API бэкенда

Со стороны бэкенда должны быть предоставлены следующие API:

1. Прочитать все заявки (с их состояниями), а также с фильтрацией — параметром состояния заявки.
2. API для расчёта максимального кредита (как его сделать, будет описание ниже).
3. API для сохранения черновиков.
4. API для отказа по заявке.
5. API для одобрения заявки.

### Требования к фронтенду

Со стороны фронта должно быть:

Интерфейс должен быть из двух частей:

1. Посмотреть все заявки с их статусами (списком).

Если заявка в статусе `«создан»`, то открывается:

2. Интерфейс, где показаны данные по заявке. В этом интерфейсе есть кнопки, которые рассчитывают риск выплаты, и оператор может нажать кнопку «сохранить в черновик» или «одобрить».

При нажатии кнопки на бэк идёт запрос с данными по заявке, и бэк должен рассчитать, какой максимальный объём кредита может быть выдан.

(Если у заявки статус «черновик», то будут показаны ранее рассчитанные данные.)

### Расчёт максимального кредита

Расчёт идёт по формуле:

- Стоимость жилья = S
- Первоначальный платёж = S0
- Годичный доход = M
- Лет выплат = N

API для расчёта максимального кредита выдаёт:

- Какая месячный ожидаемый платёж: `(S - S0) * (1.06) ^ N / (12*N)`

### Данные в ипотечной заявке

- ID заявки
- Имя
- Фамилия
- Месячный доход
- Начальный платёж
- Стоимость жилья
- Сколько лет кредита
- Статус заявки (`CREATED/DRAFT/APPROVED/DECLINED`)
- Комментарии для аналитика

### Данные в ответе на заявку (ответ — это PDF-файл)

**Отказ:**

> Уважаемый Имя, к сожалению по вашей заявке пришел отказ.

**Позитивный ответ:**

> Уважаемый Имя, ваша заявка одобрена

Ниже график выплат.
